쓱-싹 만들기

파일 정리 도구의 첫 화면부터, 파일이 많아져도 반복 작업을 줄이는 업데이트까지.

첫 기록 2026.11.03 · 업데이트 2026.11.11

이번 업데이트처음 만들던 기록다운로드·사용법

2026.11.11 — 기능이 늘어난 뒤, 성능을 다시 보기

복사본 검사에서 시작한 앱에 같은 이름 묶기, 버전 비교, 폴더 내용 비교와 파일 구조화 기능이 붙었다. 이제는 기능이 있는지만큼 파일이 많을 때 어떤 작업을 반복하는지 살펴볼 필요가 있었다.

코드를 비판적으로 읽어 보니 남길 파일 하나를 바꿔도 전체 결과를 다시 만들었고, 체크박스를 누를 때마다 목록을 정렬하고 화면을 다시 그렸다. 폴더 비교에서는 경로가 겹치지 않는 파일까지 내용을 읽었으며, 폴더를 삭제한 뒤에는 남은 전체 폴더를 다시 검사했다. 이번에는 이 반복을 줄이는 데 집중했다.

필요한 만큼만 갱신하기

용량을 새로 측정하거나 남길 파일을 변경할 때 전체 목록을 다시 보내지 않도록 바꿨다. 기존 항목의 ID를 유지하고 변경된 정보만 응답한다. 파일을 체크할 때는 목록 전체를 재생성하는 대신 선택 표시와 하단 작업 버튼을 갱신한다. 묶음마다 전체 목록을 다시 훑어 개수를 세던 처리도 한 번의 집계로 바꿨다.

일반 파일 5만 행과 같은 이름 후보 2개를 넣은 합성 데이터에서, 전체 결과 생성·JSON 변환은 약 0.45초와 12.5 MiB였다. 변경 정보만 반환한 남길 기준 갱신은 약 0.006초, 380바이트였다. 한 환경의 단일 측정이며 실제 디스크 검사나 브라우저 화면 처리 시간은 포함하지 않는다. 모든 PC에서 같은 속도가 나온다는 의미는 아니다.

파일을 덜 읽되, 이동 직전 확인은 남기기

두 폴더에서 한쪽에만 있는 경로는 목록만으로 구분할 수 있고, 같은 경로라도 크기가 다르면 이미 다른 파일이다. 이제 두 조건을 먼저 확인하고, 공통 경로에 크기도 같은 파일만 SHA-256으로 비교한다. 큰 파일을 불필요하게 읽는 일을 줄이기 위한 순서다.

삭제 직전의 검증은 유지했다. 검사 때와 파일 상태가 같은지 확인하고, 같은 경로·같은 크기의 파일도 내용을 다시 비교한다. 수정 시간을 원래대로 돌린 같은 크기 파일의 변경도 테스트로 확인했다. 정리한 폴더는 기존 결과와 용량 인덱스에서 제거해 전체 중복·ZIP 검사를 반복하지 않도록 했다.

앱의 로컬 서버는 작업 중에도 연결 확인 요청에 응답한다. 실제 상태 변경 작업은 하나씩 처리해 다른 요청과 겹치지 않게 했고, 폴더 비교에는 진행 중인 파일을 표시했다. 대용량 폴더의 읽기 자체가 없어지는 것은 아니지만 기다리는 이유를 확인할 수 있도록 했다.

검증한 범위와 남아 있는 확인

최신 소스와 이번 ZIP에 포함된 Python 3.13.17 환경에서 자동 테스트 58개를 실행했다. 57개가 통과했고, Windows에서 심볼릭 링크를 만들 권한이 필요한 1개는 건너뛰었다. 폴더 정리 후 용량 목록 갱신, 남길 파일의 ID 유지, 변경된 항목만 응답하는 동작, 불필요한 해시 생략, 작업 중 연결 확인 응답과 중복 작업 차단을 검사했다.

이 결과가 실제 화면과 모든 파일 작업의 검증을 대신하지는 않는다. Windows 휴지통 이동, 설치된 Chrome 도우미와의 연결, 다양한 배율에서의 화면 배치는 실제 사용 흐름으로 추가 확인해야 한다. 중요한 파일을 대상으로 바로 시작하기보다 예시 파일과 작은 폴더에서 먼저 확인하는 사용 순서를 안내했다.

Python을 따로 설치하지 않는 ZIP으로

이전 v0.7.1 안내에는 PC에 Python을 설치해야 한다고 적었다. 이번 배포 ZIP에는 공식 MSI의 서명을 확인한 Python 3.13.17 런타임을 함께 넣었다. 사용자는 새 폴더에 압축을 전부 풀고 ‘쓱-싹.exe’를 실행하면 된다. 화면은 Chrome 또는 Edge의 앱 창으로 열리며, Chrome 다운로드 정리만 Chrome과 연결 도우미가 필요하다.

소스 저장소에서는 런타임과 빌드 결과를 제외하고 build.py로 배포본을 만든다. 테스트는 tests/로 분리하고, 개인 연결 키·정리 결과·설정 백업·파이썬 캐시는 ZIP에서 제외한다. 웹사이트에는 실제 배포 ZIP의 SHA-256도 함께 올린다. 앱 EXE의 코드 서명은 아직 없으므로 다운로드 페이지에 계속 명시한다.

이번 공개 파일은 main의 1d5c73a 커밋으로 만들었다. 기존 v0.7.18 기능에 성능 개선과 코드 리뷰 변경을 포함한 포터블 배포본이다.

2026.11.03 — 처음 만들던 기록

아래는 v0.7.1까지 앱의 모습과 실행 방식을 다듬던 과정이다. 당시 별도로 필요했던 Python은 이번 포터블 ZIP에 포함했고, 현재 정리는 Windows 휴지통을 사용한다.

다운로드 폴더에서 시작한 도구

컴퓨터에 쌓인 파일을 정리할 때는 지우는 일보다 무엇을 남겨야 할지 고르는 일이 더 번거로웠다. 복사본이나 예전 작업 파일처럼 다시 살펴볼 항목을 모아 주고, 내가 확인한 것만 정리할 수 있는 프로그램을 만들고 싶었다. 그렇게 파일 정리 도우미 ‘쓱-싹’을 만들기 시작했다.

파일 정리 외에도 임시 파일 확인, 폴더별 용량 확인, 보관함과 복원, Chrome 다운로드 기록 정리를 한곳에서 사용할 수 있도록 구성했다. 검사 결과는 자동 삭제 목록이 아니라 사용자가 판단할 후보 목록으로 다룬다.

내 앱이라는 느낌을 만드는 아이콘

처음에는 기능을 담는 데 집중했지만, 실행하는 순간부터 앱의 인상이 만들어진다는 생각이 들었다. 빗자루와 쓰레받이 그림을 Windows 아이콘으로 만들고 v0.6.1에 적용했다. 여러 크기의 ICO를 준비해 작은 바로가기에서도 같은 이미지를 사용할 수 있도록 했다.

딱딱한 화면을 둥근 카드로

기존 화면은 기능이 있어도 오래된 관리 프로그램처럼 느껴졌다. v0.6.2에서는 메뉴, 제목, 파일 목록과 하단 버튼을 둥근 카드로 나누고, 선택한 항목은 연한 레드로 구분했다. ‘춤추는사람들’ 글꼴도 앱에 포함해 별도 설치 없이 적용되도록 했다.

이후 토스 모바일 디자인 시스템의 목록, 버튼, 글자 위계 같은 구성 방식을 참고 대상으로 삼았다. 파일 이름과 경로는 왼쪽에서 읽고 용량은 오른쪽에서 비교할 수 있도록 실제 정리 화면의 배치를 다듬었다.

CSS 화면과 간단한 실행 구조

v0.7에서는 화면을 HTML과 CSS로 다시 구성했다. 첫 화면에는 ‘폴더 선택하기’를 크게 두고, 검사 후에는 목록을 살펴보는 흐름으로 이어지도록 했다. 차분한 레드와 둥근 카드, 전용 글꼴을 유지하면서 여백과 정보의 우선순위를 정리했다.

압축을 풀었을 때는 쓱-싹.exe와 app 폴더가 보이도록 묶었다. 당시 v0.7.1 실행기는 PC에 Python 3.9 이상이 있어야 했으므로, Python까지 포함한 배포 패키지는 아니었다.

Chrome 앱 창으로 열기

v0.7의 Edge 앱 창에서 v0.7.1의 Chrome 앱 창으로 실행 방식을 바꿨다. Chrome이 설치되어 있으면 주소창 없는 창으로 화면을 열고, 찾지 못하면 기본 창으로 돌아가도록 구성했다. 브라우저 화면과 로컬 파일 처리 기능을 연결하는 구조다.

배포 파일과 배포 준비는 별개의 일

실행 파일을 만들고 나니 Windows에서 ‘알 수 없는 게시자’가 표시되는 문제도 확인하게 됐다. EXE에는 디지털 서명이 없었다. 아이콘과 이름을 바꾸는 것만으로 배포자의 신원을 인증할 수는 없다는 점을 배웠다.

v0.7.1 당시에는 실제 Windows에서 실행과 화면 배치를 확인하고 배포 방식을 정하는 일이 다음 단계였다. 코드 서명과 스토어 배포도 검토 대상으로 남겨 두었다. 이번 업데이트의 검증 범위와 배포 파일은 위 최신 기록과 다운로드 페이지에 이어 적었다.
